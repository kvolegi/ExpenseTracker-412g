# Застосування патернів проєктування (Лабораторна робота №3)

## 1. Застосовані патерни GoF

### 1.1. Factory Method (Породжувальний)
* **Класи:** `PaymentProcessor` (ABC), `CashPayment`, `CardPayment`, `CryptoPayment`, `PaymentFactory`.
* **Призначення:** Ізоляція правил комісії та обробки платежів. Новий спосіб оплати додається окремим класом без зміни бізнес-логіки створення транзакції.
* **Також:** `NotifierFactory` для каналів сповіщень Telegram та Email.

### 1.2. Builder (Породжувальний)
* **Класи:** `ExpenseData`, `ExpenseBuilder`.
* **Призначення:** Покрокове конструювання складної фінансової сутності з 8 полями, контроль дефолтних параметрів та інваріантів перед збереженням.

### 1.3. Strategy (Поведінковий)
* **Класи:** `SortStrategy` (ABC), `SortByDate`, `SortByAmount`, `SortByCategory`, `TransactionSorter`.
* **Призначення:** Гнучке перемикання алгоритмів сортування списків транзакцій за датою, сумою або категорією.

### 1.4. Observer (Поведінковий)
* **Класи:** `EventBus` (`event_bus`).
* **Призначення:** Слабке зв'язування компонентів. Після створення транзакції публікується подія `transaction.created`, на яку реагують нотифікатори та журнал аудиту без блокування HTTP-відповіді.

### 1.5. Facade (Структурний)
* **Класи:** `TransactionFacade`.
* **Призначення:** Єдиний уніфікований інтерфейс у шарі застосунку, який координує Builder, PaymentFactory, Repository, NotifierFactory та EventBus.

## 2. Зведена таблиця метрик рефакторингу

| Патерн | Проблема в коді | До рефакторингу | Після рефакторингу |
| :--- | :--- | :--- | :--- |
| **Factory Method** | Розрахунок комісій зашитий у розгалуженні `if/elif` | 1 файл, складність $O(N)$ розгалужень | Окремі класи, реєстрація через словник |
| **Builder** | 8 параметрів у сигнатурах функцій, дублювання дефолтів | Розпорошені перевірки | Ланцюжок методів `.set_*()`, чистий код |
| **Strategy** | Жорсткі умови `if sort_by == ...` у вибірці | Монолітний метод сервісу | Стратегії ізольовані в `SortStrategies` |
| **Observer** | Прямий виклик побічних дій блокував сервіс | Тісний зв'язок компонентів | Асинхронний `event_bus.publish()` |
| **Facade** | Роутер викликав 5 сервісів і репозиторіїв окремо | Висока зв'язність роутерів | 1 виклик `tx_facade.create_transaction()` |
