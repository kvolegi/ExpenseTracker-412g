# Архітектура клієнтської частини (Лабораторна робота №4)

## 1. Загальна характеристика
Клієнтська частина системи **Expense Tracker** реалізована як **Telegram Mini App** на чистому стеку: HTML5, CSS3 з користувацькими CSS-змінними (`:root`) та Vanilla JavaScript (ES6+) без сторонніх важких фреймворків, згідно з архітектурним рішенням ADR-002.

## 2. Структура файлів
* `frontend/index.html` — розмітка екранів, стилі тем (light/dark) та контролер інтерфейсу `App`.
* `frontend/api.js` (та `src/services/services.js`) — клієнтський сервісний шар: класи `ApiService` (Singleton), `Logger` (Singleton), `EventBus` (Observer) та `ExpenseBuilder` (Builder).
* `frontend/server.py` — автономний статичний HTTP-сервер на Python `http.server` з підтримкою CORS та no-cache для роздачі інтерфейсу на порті 3000.
* `frontend/railway.toml` — дескриптор розгортання статичного сервера на хмарній платформі Railway.
* `frontend/src/splash.png` — заставка стартового екрана.

## 3. Екрани застосунку та взаємодія з API
1. **Splash Screen:** стартова заставка з плавною анімацією завантаження.
2. **Login Screen:** автентифікація через `Telegram WebApp SDK` (`POST /api/v1/auth/telegram`) з автоматичним збереженням JWT-токена в `localStorage`.
3. **Головний екран (Home):**
   * Карточка балансу (загальні доходи, витрати, поточний баланс).
   * Список останніх фінансових операцій (`GET /api/v1/expenses?limit=100`).
4. **Екран огляду (Overview):**
   * Динамічна тижнева стовпчикова діаграма розподілу витрат за 4 тижнями місяця.
5. **Профіль (Profile):**
   * Відображення даних акаунта, вибір валюти та мови інтерфейсу.
6. **Модальні вікна (Modal):**
   * Створення транзакції (`POST /api/v1/expenses`) з вибором категорій (`GET /api/v1/categories`) та типу оплати (cash/card/crypto).
   * Видалення транзакції (`DELETE /api/v1/expenses/{id}`).
